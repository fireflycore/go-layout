# 数据转换流程

## 术语解释
- DAO ---- Data Access Object
  - 数据访问对象，是用于封装对数据源的访问的对象，它提供了对数据库的增删改查，而不暴露数据库的内部细节
  - internal/data/* 定义于此，根目录下就是实现biz repo的DAO
  - 在firefly中，DAO层通常位于数据访问层，负责与数据库/其他服务进行交互
- DTO ---- Data Transfer Object
  - 数据传输对象，用于在进程之间（如客户端和服务器之间，或者服务内部不同层之间）传输数据的对象
  - 在firefly中，DTO一般是`grpc proto`中定义的，通过`buf-cli`生成对应的代码，生成的代码一般位于`depend/protobuf`下
- DO ---- Domain Object
  - 领域对象，是业务领域中的实体，它包含了业务逻辑和数据。在DDD（领域驱动设计）中，DO是领域模型的一部分
  - 在firefly中，DO一般定义于`internal/biz/model`中
- PO ---- Persistent Object
  - 持久化对象，与数据库表结构一一对应的对象
  - 在firefly中，PO一般定义于`internal/data/entity`中

## 数据转换
- 数据转换依托于`goverter`，通过定义数据转换接口，然后生成数据转换方法
- `DTO <---> DO`转换接口定义于`internal/service/convert`中
- `DO <---> PO`转换接口定义于`internal/data/convert`中

## 数据验证
- 数据验证依托于`buf-cli`的`buf validate`插件，生成grpc代码后，使用`buf.build/go/protovalidate`验证字段是否合法;
- 在firefly中通常在service层中调用`protovalidate.Validate(request)`仰正字段是否合法；

## 目录结构
biz/
    repo/ ---- 定义data的repo接口
    model/ ---- 定义业务领域模型

data/
    convert/ ---- 定义`DO <---> PO`的转换接口
    entity/ ---- 定义数据模型

service/
    convert/ ---- 定义`DTO <---> DO`的转换接口
