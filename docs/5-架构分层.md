## 架构分层

1. 配置层 (internal/conf)
   - 职责：统一管理应用配置，支持多配置源
2. 业务逻辑层 (internal/biz)
   - 职责：实现核心业务逻辑，保持框架无关性
3. 数据访问层 (internal/data)
   - 职责：数据持久化实现，封装数据库细节
4. 应用服务层 (internal/service)
   - 对外提供 API 服务，处理协议转换
5. 服务层 (internal/server)
   - 服务注册、网络层处理

## 集成工具
- goverter: 用于生成数据转换代码，避免手动编写重复代码;
  - https://goverter.jmattheis.de/
- buf-cli: 用于管理proto和生成grpc代码;
  - https://buf.build/docs/

## 注意事项
注意：本项目是一个单独的服务，拥有独立git仓库，并非传统的大仓;
注意：本项目的proto定义是在统一proto仓库中，通过buf-cli进行管理和生成相关grpc代码;
注意：本项目不需要冗余的数据转换，按业务在biz/convert下定义数据转换，如非必要直接使用buf-cli生成的代码;
   - 本项目无冗余数据转换，且视所有的数据转换概念为DTO
     - 无DO->PO概念
     - 无PO->DO概念
     - 无DTO->DO概念
     - 无DO->DTO概念
   - 数据转换逻辑
     - 能用现有的就用现有的，无需重复定义，浪费性能，增加心智负担
     - biz/model 下定义业务数据模型，
     - biz/convert 下定义业务数据模型转proto数据模型的接口
     - dto/ 下定义biz/convert下的实现
